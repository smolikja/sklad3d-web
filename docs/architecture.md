# Architecture

This document describes the stable boundaries of the SKLAD website. It is
organized by subsystem rather than as a catalog of every React component.

## Route families

| Public route | Implementation | Responsibility |
| --- | --- | --- |
| `/{locale}` | `src/app/[locale]/page.tsx` | The localized landing page, its metadata, structured data and Open Graph image. Content URLs are always prefixed: `/cs` and `/en`. |
| `/` and any unprefixed path | `src/proxy.ts` | 307 redirect to the visitor's locale (cookie → `Accept-Language` → default). |
| unmatched `/{locale}/…` | `src/app/global-not-found.tsx` | Fully server-rendered, localized 404 with its own `<html lang>`. |
| `/robots.txt`, `/sitemap.xml`, `/manifest.webmanifest`, `/icon.png`, `/apple-icon.png`, `/favicon.ico` | Metadata files in `src/app/` | Search-engine and install metadata generated by Next.js file conventions. |
| `/images/*`, `/brand/*` | `public/` | Photos, posters, logo, PWA icons. Static; never redirected. |

Both locale pages are prerendered at build time; only the proxy and the image
optimizer run per request.

## Server and client boundaries

Server Components are the default. They load the dictionary, build metadata
and compose the page without shipping message catalogs to the browser.

Client islands:

| Island | Why it is client-side |
| --- | --- |
| `landing/mobile-menu.tsx` | Open/close state of the small-screen menu (shadcn `Sheet` on Base UI). |
| `landing/member-gallery.tsx` → `ui/carousel.tsx` | Embla row of a member's work (drag, trackpad wheel, arrow keys, buttons, progress) and which item the lightbox shows. |
| `landing/media-lightbox.tsx` | Full-screen dialog (Base UI) with stepping, keyboard control and focus return to the slide. |
| `landing/showcase-video.tsx` | Plays a muted preview only while visible, respecting reduced motion and data saving. |
| `ui/accordion.tsx` (FAQ) | Expand/collapse (Base UI accordion). |

Everything else is a Server Component, including the hero's load animation
(`landing/subpixel-photo.tsx`), which is pure CSS. Values crossing into client
components are serializable plain data.

Language switching is plain links (`layout/language-switcher.tsx`) — visiting
`/en` makes the proxy remember the choice in the `NEXT_LOCALE` cookie, so it
works without JavaScript. The application is an external form
(`siteConfig.applyHref`); the site has no Server Actions and no secrets.

## Source ownership

| Location | Owns |
| --- | --- |
| `src/app/` | URL structure, the layout, page composition, metadata, structured data and the global 404. |
| `src/components/landing/` | Page sections in reading order (`landing-page.tsx`) and their small helpers (`section.tsx`, `section-heading.tsx`, `apply-link.tsx`, `rich-text.tsx`, `media.ts`). |
| `src/components/layout/` | Shared layout helpers (language switcher). |
| `src/components/icons/` | The SKLAD mark and third-party brand marks. |
| `src/components/ui/` | Generated shadcn primitives (Base UI + `cva`). Regenerate with the CLI; do not hand-edit their API. |
| `src/config/` | Locale-independent structural data: site URLs, address, navigation, benefit order, brand and place assets, members and their media. |
| `src/i18n/` | Locale types, language negotiation, dictionary loading and template formatting. |
| `src/lib/` | Shared utilities: fonts, `cn()`, metadata helpers, bio markup parsing, share-image rendering. |
| `messages/` | Localized user-facing copy. |
| `public/` | Static assets served from the site root — see [Web assets](assets.md). |
| `scripts/` | Repository tooling (`check-docs.mjs`). |

## Data flow

The locale segment is validated against `src/i18n/config.ts`. The page loads
the matching typed catalog, and `landing-page.tsx` passes each section only
the dictionary subtree it renders, in the original reading order: hero → how
SKLAD works → members → benefits → community → FAQ → closing call.

Members come from `src/config/members.ts` (order, names, avatar, links, media
with pixel sizes) joined with `dict.members.items[id]` (role, bio, link
labels, media descriptions). `src/i18n/dictionaries.ts` refuses a catalog that
lacks copy for a configured link or media item. The same data feeds the
`LocalBusiness` structured data (members as `Person`) and the image entries of
the sitemap.

## Styling

Tailwind v4 with the shadcn `base-nova` preset. Semantic tokens are defined
once in `src/app/globals.css` as a single dark theme (`<html class="dark">`):
true black background, concrete-grey surfaces, mint `--primary`, and the
logo's `--subpixel-r/g/b`, which are reserved for the mark and the hero photo.
Components use semantic utilities (`bg-card`, `text-muted-foreground`,
`bg-primary`) — never raw colours.

The page column is three tokens in `globals.css`: `--page-max`,
`--page-gutter` and the derived `--page-inset` (viewport edge to column
edge). The container uses the first two; the member galleries break out to
the full window width and pad by `--page-inset`, so they scroll under both
window edges while their first, last and resting pieces line up with the
column.

Every section, the hero included, is at least one full screen tall
(`min-h-lvh`; the sticky header is not subtracted) with its content vertically
centred, so each topic gets its own screen. Longer sections, such as the
members, simply grow.

Type is one variable family, Archivo (`src/lib/fonts.ts`); its width axis
carries the hierarchy — `font-display` (125 % width, 800) for section titles,
112 % for the hero and card titles, normal width for reading text. Primary
controls are 48 px tall.

Motion is limited to the hero photo converging from its RGB channels on load
and to responses to the visitor's actions (menu, lightbox, accordion). All of
it is disabled under `prefers-reduced-motion`.

## Sources of truth

- User-facing copy: `messages/<locale>.json`, typed by `src/i18n/dictionary.ts`.
- Supported locales and URL behaviour: `src/i18n/config.ts` and `src/proxy.ts`.
- Site URL, application form, address, external links, navigation: `src/config/site.ts`.
- Members, their links and media: `src/config/members.ts`.
- Brand and place assets: `src/config/assets.ts`.
- Dependency versions and commands: `package.json`.
- Deployment commands: `nixpacks.toml` and `next.config.ts`.

Documentation should explain why these values matter and how systems
interact; it should link to the source rather than copying change-prone
values.
